The Strategy

Strangler Fig — No Big-Bang Rewrite

Why Strangler Fig?

  • Monolith keeps running throughout — zero downtime
  • Each extraction is independently deployable
  • Rollback is a feature flag flip, not a deployment
  • Business continues while engineering migrates
  • Each seam is proved by characterization tests before being cut

The Invariant

Characterization tests must be GREEN before AND after every single commit.

If they break → revert. No exceptions.

The Proxy Router (Nginx)

upstream freight-service { server freight:8080; }

Challenge 4 — The Pin

Characterization Tests — Pin Before You Cut

What They Are

Tests that record what the code does — not what it should do. Bugs are pinned deliberately.


Golden Rule:

Never change a characterization test to make it pass after a code change. If behavior changes intentionally, update the test AND document why.

Bugs Intentionally Pinned

  • Florida ZIPs (320–349) → zone 4 (should be 5–6)
  • Chicago→LA → zone 6 (should be 8)
  • Fuel surcharge: $47.82 → $51.88 (not $51.90)
  • helpers.php gives different rate than FreightCalc.php

        $GLOBALS['passed']++;

Challenge 6 — The Fence

Anti-Corruption Layer — Legacy Stays Contained

The ACL Rule

The new service's API is clean and permanent.
The ACL is always in the monolith, never in the Java service.

The Java service has no idea what wt_lbs, cust_id, or FDX are.

Field Translation Map

PHP (legacy)→Java (clean)
$order['wt_lbs']→weightLbs: Double
$order['origin_zip']→originZip: String
'FDX' carrier code→"FEDEX"
'USP' (typo)→"USPS"
$result['rate'] float→totalRate: BigDecimal
cents int (×100)←dollars BigDecimal
 
// modules/acl/FreightServiceAdapter.php

class FreightServiceAdapter {
  public function getRate($orderId) {

    // Translate legacy → new service contract
    $order = OrderManager::getOrder($orderId);
    $payload = json_encode([
      'weightLbs'  => (float) $order['wt_lbs'],
      'originZip'  => $order['origin_zip'],
      'destZip'    => $order['dest_zip'],
      'carrier'    => $this->mapCarrier($order['carrier_code'])
      // wt_lbs = 2008 shortcode, weightLbs = clean domain name
    ]);

    $response = $this->postJson('/api/freight/rate', $payload);

    if (!$response) {
      // Fallback to legacy on any failure
      return FreightCalc::calculateRate($orderId, ...);
    }

    // Translate response back to legacy format
    return [
      'rate_cents' => (int)($response['totalRate'] * 100),
      'zone'       => $response['zone'],
      'est_days'   => $response['estimatedDays'],
    ];
  }
}

Flip to false → old path. Rollback in 30 seconds.

Challenge 10 — The Weekend

Cutover Runbook — The One Ops Will Actually Follow

13-Point Pre-Cutover Checklist

  • Freight service health → {"status":"UP"}
  • 43/43 characterization tests green on new service
  • Rate comparison: old vs new within $0.01
  • Florida ZIP zone-5 bug preserved in Java service
  • All 8 carriers seeded in freight_rates DB
  • Rollback tested in staging within 7 days
  • On-call paged and acknowledged
  • +5 more freight-specific checks

9 Rollback Triggers (abort NOW if)

  • Error rate > 2% for 5 consecutive minutes
  • P95 latency > 800ms (was 200ms)
  • Any invoice total mismatch > $0.01
  • Any characterization test failure
  • 5xx for any carrier
  • Rate divergence > 5% in shadow mode

Roadmap

Migration Phases — Incremental, Never Big-Bang

  • Strangle NOW

    Nginx routes selected paths to Java services. ACL translates data shapes. Feature flags control rollout. Monolith fully operational throughout.

  • Isolate NEXT

    Each extracted service owns its Postgres DB. No direct DB access between services. Kafka carries state changes. Dual-write bridges the gap during transition.

  • Cut Over SPRINT+2

    Feature flag flipped to 100%. ACL remains 30 days for rollback window. Characterization tests run against live traffic. Both paths verified identical output.

  • Decommission DAY 30

    30-day clean run → delete PHP module. Remove ACL. Drop legacy MySQL table (after backup). Remove feature flag from all configs. Close migration epic.

Customer Service → Invoice Service → Order Service (God Class) follow the same four phases, in that order. The Order Service is last — its circular deps must be fully resolved before extraction begins.

Key Takeaways

Characterization tests BEFORE any cut — pin behavior, not correctness
ACL lives in the monolith — new service stays clean
Strangler Fig = zero big-bang risk — rollback is a flag, not a deploy
Outbox pattern = no dual-write race conditions, ever
One DB per service — no shared schema, no coupling
Independent CI/CD — a broken monolith never blocks a service deploy
Contract tests — if one side changes, the other screams immediately
Bugs in the old system are features to be preserved, not fixed during extraction
The runbook is written BEFORE cutover — not during the 3am incident
API Gateway is the single public face — services stay internal

Modernization is not a technology problem. It is a discipline problem.

The right patterns + the right order + the right safety nets = a monolith you can incrementally replace without ever taking it down.
